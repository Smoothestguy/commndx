# Architecture rules
- Public intake uses service-only transactional contact/application reuse; retry only transport failures with a stable payload, and keep token-scoped 24-hour session drafts including private upload references.
- Project writes strip legacy customer fields; billing resolves customers from each entry's location and fails closed for inaccessible locations, preventing cross-customer invoices.
- Phone Home uses scoped light tokens and shared self-only My Day/guarded manager actions; explicit linked field users may access only mobile Home while other portal restrictions and desktop rendering remain unchanged.
- Phone profile defaults come from self-only active sites or the user's last selected eligible site in session storage, never a named event or an arbitrary manager directory row.
- Event tabs reuse aggregate deployment totals; location detail owns operational views, and legacy tab redirects preserve bookmarked destinations without widening permissions.
- Lazy routes retain the eager shell; shared workspace navigation replaces the active view, optional tabs retain user-scoped LRU/pins, router history owns URLs and dirty blocking, and shell restores entry-keyed scroll without rewriting page filters.
- Archived applicant purging requires an exported snapshot and explicit manager confirmation to protect history.
- Punch-time frozen schedules drive counted stay timestamps; actual taps remain immutable, and approved exceptions recount through guarded triggers while audited manual overrides bypass clamping.
- Signature saves and kiosk freshness validate original actual tap identity, not a future clamped shift start.
- Scheduled auto-close uses frozen shift boundaries and guarded accrual, never actual-out evidence; notices reserve per-stay keys before sending and use the frozen scheduled end with location/project timezone fallback. Token-scoped open events and worker-reported corrections remain separate from device punches and manager-only GPS reads. Closure SQL regressions run with rollback in an isolated database, never by granting sandbox privileges or changing owner records.
- Shared grids own the top toolbar (quick-filter pills driven by page state, all-column search, Filters, Columns show/reorder persisted per table in localStorage); cells hold one value, so badges/flags get their own columns.
- Row selection uses transient screen-scoped state with legacy-key cleanup; filter/session preferences remain separate so navigation never carries bulk-action targets into another screen.
- Server-backed grid search keeps immediate input state separate from its debounced query value and retains previous query data; only initial no-data loading may replace the grid, preventing focus loss.
- Contact dedupe: DB triggers normalize email/phone only when those columns change; staff create paths call `find_contact_matches` first; worker verified stamps come only from server-consumed one-time code proofs or the invite link's own channel, and code delivery failures never block intake or onboarding.
