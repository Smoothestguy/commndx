# Asset rules
- Global Locations uses paginated counts-only staffing and shared operational authorization; location review queries constrain both project and location IDs to prevent cross-site approvals.
- Event summaries derive location customers in a paginated shared projection; retained project customer only supplies compatibility defaults. Customer-token reads/submissions scope to the location customer to prevent cross-customer access.
- Read asset catalog/placements through authenticated role-aware projections; keep base financial rows manager/admin-only to protect costs beyond presentation gates.
- Append custody history separately from placement periods; lifecycle triggers release current responsibility without splitting customer billable days.- Asset allocated cost/day is derived on read from asset cost inputs via `src/lib/assetCost.ts` (never stored); cost fields travel only in the manager/admin block of the catalog projection.
- Equipment per-diem billing is derived on read from `asset_assignments` (location_id, billable, day_rate ?? assets.default_day_rate) via `src/lib/assetBilling.ts`; never store accrued totals, so project, location and financial views stay consistent.
- TO creation shares dated current-level drafts; demobe stays use the guarded manual path, same-location accepted order FK and unique order/person key, so ledger source/billing/audit persist without duplicate retries or changing authorization history.
- Project vendor membership uses soft-active unique pairs and minimal staff name reads; project pickers never default globally, existing employers/links retain history.
- Project personnel choices use the minimal active roster RPC and shared AddToProject; dated worked-history eligibility remains separate so deactivation never erases evidence. Roster additions never send messages.
- Structured TO terms and allocations use manager-authorized transactions and derived signed-source billing; private sheet snapshots never mutate punches, and worked-day allowances deduplicate across TO splits to avoid double charges.
