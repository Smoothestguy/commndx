# Architecture rules
- Location manual time controls use the existing manual-visit saver, locked location/active roster scope and location-timezone conversion; timed grid saves replace hours-only writes. Existing stay edits target visit_personnel only, guard original/proposed days and closed payroll weeks, reopen sheets with versions, recompute attendance and share cache invalidation. Audits mark edited stays without rewriting their source or signatures; per-stay deletion retains private evidence and voids detached financial accrual instead of deleting financial rows. Client multi-write guards do not claim atomic lock enforcement.
- Agency public pages use only live vendor-token RPCs and recursive allow-list schemas; weekly matrices and dynamic XLSX share the same hours-only projection. Manager vendor logo saves are isolated from financial sync and use unique public image paths; removal clears metadata without deleting shared objects. Worker agency branding comes only from token info, never directory joins.
- Staff entity navigation uses real React Router anchors and shared context actions; URL state pushes discrete choices and replaces typing. Location pages reuse scoped project views with explicit filtering, preserving private evidence and existing permissions; location-list scroll is restored per history entry.
- Customer public portal uses only token-validated RPCs with recursive allow-list schemas, never authenticated staff hooks; scoped light tokens preserve the staff theme. Portal messaging remains customer/project scoped, remembers only composer name, and renders plain text; manager decisions guard submitted status and retry requirement sync without reaccepting. Staff threads mark only loaded customer messages read.
- Location customer authorizations use live accepted-task-order RPC totals by date, separate from financial project task orders; explicit TO saves sync with sync-only retries. All direct requirement writes use the shared manual-history saver without sync, staging non-authorizing evidence and recording role deltas plus explicit current-state legacy baselines. Preserve failed headers and report partial saves; no atomic multi-request guarantee is claimed without a transactional RPC. Customer task-order extras use a token-validated minimal-response function around the existing submission/history RPCs because those RPCs omit the new fields; never grant anonymous table access. Shared paginated read caches compare active roster/assets; customer PDFs resolve historical authorization on generation and never rewrite locked evidence. Location assignment unassign preserves its row; reassign restores it because the live unique key allows only one location/person pair.

- Project join registration uses only live anonymous RPCs and strips unexpected punch/identity fields; public success is request confirmation only. Shared project-batched staff request lists use live approval/denial RPCs; approval texts resolve recipient and token from committed server records. Existing message IDs reserve one notification per request, retry only explicit failures and preserve uncertain delivery without reapproving. Link management retains manager RLS/exclusive employers. Never log/store join or personal punch bearer links; approval message audit omits the private link.

- Staff applicant locations use the shared applicant location formatter and a view-level cached ZIP batch lookup; preserve applicant fields and resolve fallbacks only for display to avoid per-row requests and unnecessary writes.
- Equipment per-diem billing is derived on read from `asset_assignments` (location_id, billable, day_rate ?? assets.default_day_rate) via `src/lib/assetBilling.ts`; never store accrued totals, so project, location and financial views stay consistent.
- Use Chicago midnight segmentation for payroll timesheets; operational attendance/visits use location-local days and cached location shift overrides, keeping payroll detail separate from server-owned time-entry accrual.
- Public punch offline support uses a generated Workbox worker scoped to `/punch/`, registered only in published top-level contexts; never cache auth/API responses or register in previews. Durable per-token intents retain GPS/time and use Web Locks plus state reconciliation before toggle retries to reduce duplicate punches without changing server logic.
- Document signatures use token-validated `document-sign` for public reads/writes and authenticated role checks for sends; private object paths and no-overwrite signature uploads preserve evidence. Staff signature queries are project-batched. Placement uses PDF.js crop/rotation geometry and normalized top-left coordinates; the shared dynamic PDF-lib generator maps into PDF bottom-left coordinates and retains certificates, so individual and ZIP exports agree without persisting generated PDFs.
- Field Mode and public document signing share the pointer-event SignaturePad to keep phone drawing behavior consistent.
- Project document selection never starts network writes; explicit submission owns busy state and prevents dismissal while uploading so reopened native file inputs cannot inherit an invisible upload.
- Project employer tags use an authenticated project-scoped minimal-projection function because the staff directory omits employer links; never widen personnel/vendor/customer access or expose financial fields for labels. Shared employer maps separate customer employers from vendor-only agency filters/exports; exports allow-list hours-only columns and filter vendor plus selected Chicago week independently of screen filters. Personnel forms normalize mutually exclusive employer IDs before saving.
- Customer sign-in sheets use a pure location-timezone/day segmentation and PDF layer separate from Chicago payroll; paginated project trail and batched evidence reads feed it, so later lock/countersign phases can preserve generated evidence without changing payroll.
- Built-in customer daily PDFs aggregate stays per person after local-day segmentation; uploaded linked templates take precedence, and nullable document references use the same manager-authorized immutable approval/version pipeline. Project-scoped minimal agency metadata also carries personnel non-billable flags; attendance remains complete while monetary calculations fail closed until those flags load.
- Reusable sign-in templates copy document metadata and fields but share private storage originals; client deletion must never delete shared files because cross-project references may be hidden by RLS.
- Location geocoding is manager-authorized in an edge function; address and manual-coordinate timezone resolution use the same entrypoint, and secret Mapbox tokens are never returned to browsers.
- Already-signed public punch history is read through a token-validated minimal-response edge function scoped to that token's person, location and recent local day; never grant anonymous trail access.
- Deployment/roster operational hours use paginated time_entries while punch trail remains detail; assignment/status counts share one hook to prevent list/header cache-shape conflicts.
- Public punch signatures use an expiring-token edge function and immutable private storage paths; committed queue intents retry only the signature write, never toggle an already accepted punch.
- Customer sheet approvals use manager-authorized functions, verified SHA-256 and immutable version paths; reopening reserves the next version with a reason before attendance/time mutations. Shared-file template originals and prior signed PDFs are never overwritten.
- Kiosk signatures use an expiring location-token/active-roster function around the live kiosk RPC; expected-state reconciliation prevents stale UI toggles, and signature-only retries target the committed stay without punching again.
- Sign-in reconciliation is server-recomputed from paginated minimal projections; evidence fingerprints invalidate stale acknowledgments. Week close locks and verifies every source before recording closure; the live schema lacks an atomic close RPC, so direct-write race protection is not claimed.
- Scheduled sign-in jobs validate service credentials in code, reserve alert keys before sending, and never return punch links or credentials. Delivery verifies private PDF hashes and uses provider idempotency; optional Drive service-account keys stay server-only.
- Shift discipline uses a token-scoped minimal public status read and authenticated staff Field Mode punches through the live site RPC; manager-only review preserves early evidence and extensions, while durable intents retain effective server times and early reasons separately from GPS overrides.
- Kiosk modes travel in generated URLs; default public info omits roster names, searches use the bounded live RPC, selected photos use short private URLs, and document-sign kiosk_media validates active roster and matching recent open stays with immutable private paths. Badge scans use live server punches; Field Mode scans retain authenticated signature/shift enforcement. Agency submission attribution is server-owned and never accepts arbitrary applicant IDs; existing applicant attribution is preserved unless a valid applicant-specific quick invite proves the relationship.
