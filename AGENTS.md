# Architecture rules

- Staff applicant locations use the shared applicant location formatter and a view-level cached ZIP batch lookup; preserve applicant fields and resolve fallbacks only for display to avoid per-row requests and unnecessary writes.- Equipment per-diem billing is derived on read from `asset_assignments` (location_id, billable, day_rate ?? assets.default_day_rate) via `src/lib/assetBilling.ts`; never store accrued totals, so project, location and financial views stay consistent.
- Use shared Chicago midnight segmentation for timesheets and visit-derived attendance, with location shift overrides threaded from cached project locations, so exports and calendar-day attendance stay consistent without extra location queries.
- Public punch offline support uses a generated Workbox worker scoped to `/punch/`, registered only in published top-level contexts; never cache auth/API responses or register in previews. Durable per-token intents retain GPS/time and use Web Locks plus state reconciliation before toggle retries to reduce duplicate punches without changing server logic.
- Document signatures use token-validated `document-sign` for public reads/writes and authenticated role checks for sends; private object paths and no-overwrite signature uploads preserve evidence. Staff signature queries are project-batched, and signed-copy exports dynamically append certificates to original PDFs.
- Field Mode and public document signing share the pointer-event SignaturePad to keep phone drawing behavior consistent.
